# LongHorizonOS v0.1.0 — Experimental single-host release

LongHorizonOS is an OS-inspired Python runtime for managing long-running,
stateful Agent computation.

> **Harnesses make long-running Agents possible; LongHorizonOS makes
> long-running Agent computation efficient.**

> **Graph represents the evolving computation; the OS continuously schedules
> from the Graph.**

The release boundary is deliberately narrow: **v0.1.0 is a single-host
research alpha**, not a production or distributed Agent OS. It provides
graph-relative verified repair, bounded online compute-control primitives, and
Kernel-fenced execution ownership.

## What v0.1.0 establishes

### Semantic control plane

- A versioned Verified Progress Graph (VPG) is the authority for Goal, Task,
  Artifact, Evidence, dependency, validity, readiness, invalidation, Repair
  Frontier, and Goal-closure state.
- Evidence is bound to exact Artifact versions. Superseded Evidence remains an
  auditable historical fact but cannot prove the current version.
- Deterministic causal invalidation marks only the graph-relative affected
  closure stale and preserves unaffected `VERIFIED` work.
- Verifier-backed semantic completion is fail-closed: executor success alone
  does not close a task or Goal.

### Scheduling, execution, and ownership

- Deterministic Agent eligibility and matching, Claims, Attempts, retries,
  logical resource admission, Kernel Leases, fencing tokens, and
  reconciliation.
- Public `AgentOS.run(...)` and bounded `AgentOS.run_async(...)` paths.
- Exact Claim/Attempt/epoch/Lease-generation validation before Evidence/VPG
  commit, preventing a superseded worker from closing current semantic state.
- Durable VPG and optional Scheduler projections with integrity checking and
  bounded replay/recovery.
- Context snapshots and Agent cognition/provenance snapshots on the bounded SDK
  Attempt path.

### Integrations and operator surfaces

- Experimental public SDK and CLI.
- OpenAI-compatible transport with an offline fake.
- Capability-governed Workspace, Shell, Git, HTTP-read, and command-verifier
  adapters.
- Read-only status/inspection commands and deterministic demos/benchmarks.
- A Transactional Outbox primitive with **at-least-once**, not exactly-once,
  delivery semantics.

## Current source addendum — August 16, 2026

The current checkout contains additional research-alpha work after the
original v0.1.0 baseline. It remains package-versioned `0.1.0`; these additions
are recorded under [`Unreleased`](../../CHANGELOG.md#unreleased) rather than
being presented as a new stable version:

- **Mediated workspace commit fence:** exact bytes observed through the
  workspace provenance gateway are checked again before semantic Evidence
  commit. Changed, deleted, unavailable, or truncated known reads fail closed.
- **Caller-owned workspace watch loop:** declared workspace changes can be
  polled, observed, reconciled, and routed through bounded semantic-interrupt
  epochs. This is not a universal or background world watcher.
- **Bounded fresh-Attempt rebase handoff:** live `REBASE`/`FULL_RELOAD` can
  persist a handoff intent, fence and release old ownership, admit a fresh
  Attempt, detach the old Harness binding, and support idempotent recovery.
  The transfer is release-then-acquire, not a cross-plane atomic transaction.
- **Resource-aware main path:** opt-in `resource_aware=True` batching fits
  explicit task resource vectors to current logical pool capacity before the
  existing Scheduler revalidates and admits work. Host telemetry can be mapped
  explicitly to one logical pool; no physical placement or isolation is
  implied.
- **Graph-utility frontier ranking:** opt-in
  `FrontierPolicy(ranking_strategy="graph_utility")` preserves repair and
  safety constraints while ranking safe candidates by declared critical-path
  position, immediate downstream unlock value, and deterministic tie-breaks.
- **Real local wall-clock adaptive-runtime gate:** the CLI benchmark executes
  actual asynchronous waits through the public
  `AgentOS.run_async -> Scheduler -> Claim -> Kernel Lease -> worker ->
  verifier -> VPG Evidence` path.
- **Outbox zero-delay correction:** a retry with zero delay remains immediately
  eligible at the caller-supplied logical dispatch time after asynchronous
  publisher failure. Positive backoff remains completion-relative, and
  Claim-expiry fencing is unchanged.

These are bounded primitives. They do not turn the project into an autonomous
daemon, universal Harness controller, or production control plane.

| Metric | Static | Adaptive |
|---|---:|---:|
| Scheduling epochs | **3** | **2** |

## Known boundaries

The following are **not** provided by v0.1.0 or the August 16 source addendum:

- automatic discovery of arbitrary hidden filesystem, Python, API, browser,
  tool, or semantic dependencies;
- a universal always-on world watcher;
- one atomic transaction spanning Scheduler, Kernel, Harness, VPG, Facts,
  workspace state, and external effects;
- sink-enforced exactly-once delivery for payments, email, deployments, or
  other irreversible effects;
- killable process/container isolation for arbitrary Python callbacks;
- physical CPU/GPU/RAM/VRAM placement, isolation, quotas, fairness, or
  topology-aware scheduling;
- distributed scheduling, leader election, multi-host placement, or supported
  multi-writer coordination;
- automatic utility-learned provider/model/context/verifier routing;
- universal belief revision or contradiction resolution;
- statistically powered real-LLM, real-GPU, or direct-competitor evaluation.

Logical CPU/RAM/GPU/VRAM/model-slot values are admission reservations, not
proof of physical device control. Correctness and minimum repair are relative
to the dependencies and changes that the system actually observes.

## Install and run

```bash
python -m pip install -e .

lhos demo recovery-repair --json
lhos benchmark semantic-repair --quick --json
lhos benchmark wallclock-adaptive-runtime --json
```

The commands above require no API key.
