# LongHorizonOS v0.1.0 — Experimental Release

LongHorizonOS is an OS-inspired **single-host Python runtime** for long-running
stateful Agent workflows. Its central question is not only “what should run
next?” but also “which completed work is still valid after the world changes?”

> **Most agent frameworks answer what should run next. LongHorizonOS also
> answers what remains valid after the world changes.**

This release combines a Verified Progress Graph (VPG), exact-version Evidence,
versioned Artifacts, deterministic scheduling, Kernel Lease ownership,
bounded async execution, durable projections, recovery, and selective repair.
It is a reproducible systems prototype with an experimental SDK—not a
distributed Agent OS or stable production platform.

## System model

1. **VPG:** derives semantic validity, readiness, invalidation, Repair
   Frontiers, and Goal closure.
2. **Scheduler:** selects eligible work, creates Claims/Attempts, and admits
   complete logical resource vectors.
3. **Kernel:** grants exclusive execution ownership through Leases and fencing.
4. **Agents/tools:** perform attempts and produce verifier-backed
   Artifact/Evidence facts.

The authority boundary is deliberate: the graph owns semantic truth, the
Scheduler owns policy, the Kernel owns execution authority, and an Agent cannot
self-report semantic completion.

## Included surfaces

- Experimental public SDK: `AgentOS`, `Agent`, `Goal`, `Task`, `RunResult`,
  `RepairOutcome`, `StatusSnapshot`, typed errors, executors, and verifiers.
- Synchronous and bounded asynchronous Agent execution. `run_async` supports
  sync or async Agent executors and verifiers, global/per-Agent concurrency
  limits, atomic logical resource admission, cancellation cleanup, and fenced
  Evidence commits. The synchronous `run()` path rejects async callbacks.
- Fail-closed exact-version verification: a successful operational return
  without applicable Evidence remains unverified.
- Durable VPG projection snapshots, changed-entity revision history,
  historical reconstruction, hash verification, retention/compaction, and
  explicit trusted migration tooling. `READY_FRONTIER_UPDATED` events use a
  compact `summary-v1` count plus SHA-256 digest; legacy full-list payloads
  remain readable.
- Optional durable Scheduler event/state replay with hash-chain and projection
  integrity checks, Claim/Attempt/idempotency recovery, and logical
  reservation restoration.
- OpenAI-compatible transport with an offline fake, plus capability-governed
  Shell, Workspace, Git, and command-verifier integrations.
- Read-only observability CLI and explicit VPG lifecycle commands.
- Deterministic recovery/repair and async AgentOS benchmark gates.

Arbitrary Python callbacks are convenient integration hooks but are not
automatically isolated by a Kernel sandbox. The Transactional Outbox is an
at-least-once delivery primitive, not an exactly-once external side-effect
protocol.

## Benchmark evidence

### Semantic repair

`lhos benchmark semantic-repair --quick` runs 24 deterministic mutation and
repair trials plus a real temporary-workspace scenario:

| Metric | Reference result |
|---|---:|
| Valid trials | **24 / 24** |
| Mean weighted work saved vs full restart | **48.6427%** |
| Mean saving vs oracle task-DAG checkpoint | **0%** |
| Under/over-invalidation | **0 / 0** |
| False `VERIFIED` states | **0** |
| Ownership conflicts | **0** |
| State-only false closures | **24 / 24** |

This supports safe selective repair and preservation versus full restart on the
included workloads. It matches, rather than beats, the oracle task-DAG
checkpoint on these task-level graphs.

### Async AgentOS

The checked-in public-SDK workload uses 24 independent I/O-shaped tasks, two
Agents, global concurrency four, per-Agent concurrency two, an independent
verifier, and a complete logical resource vector:

| Metric | Serial | Concurrent |
|---|---:|---:|
| End-to-end time | **1.516 s** | **0.789 s** |
| Peak executor concurrency | **1** | **4** |
| Verified tasks | **24 / 24** | **24 / 24** |
| Completed Claims / semantic Attempts | **24 / 24** | **24 / 24** |
| Ownership/resource/capacity violations | **0** | **0** |

Measured speedup is **1.921x**. This is an offline controlled microbenchmark;
it does not establish model throughput, CUDA utilization, physical resource
isolation, distributed scheduling, or arbitrary-workload speedup.

### VPG durable history

For one new Task node per commit:

| Patches | Revision rows | Database | Total commit time |
|---:|---:|---:|---:|
| 100 | 100 | 483,328 B | 0.895 s |
| 200 | 200 | 888,832 B | 4.032 s |
| 400 | 400 | 1,638,400 B | 17.202 s |

At N=400, changed-entity revisions replace the former 80,200 full-copy
history rows (previously measured at about 37.9 MB), reducing history rows by
99.50%. The READY-frontier event payload is **47,892 B** at N=400 and uses the
compact `summary-v1` count-plus-digest encoding. Durable history and event
payload growth are linear for this workload, but full projection derivation,
validation, and hashing remain superlinear; these local timings are not a
latency or throughput guarantee.

For compact event rows, `get_events()` exposes
`ready_frontier_count`/`ready_frontier_hash`; callers that require the current
ordered task IDs should use `query_ready_frontier(graph_id)`. Legacy event rows
that stored the complete list remain readable.

## Release validation status — August 12, 2026

The release candidate passed:

- Multi-Agent Scheduler tests: **306 passed**;
- public SDK/CLI/demo/benchmark surface: **182 passed**;
- focused release regression set after packaging changes: **212 passed**;
- Ruff, formatter, Mypy, and Compileall gates;
- wheel and sdist build plus `twine check`;
- fresh-virtualenv wheel install and outside-repository
  `lhos demo recovery-repair --json` smoke.

Two non-blocking research-alpha caveats remain:

- the complete non-slow suite collected 2,683 tests but did not finish inside
  the 600-second local Windows validation window, so this release does not
  claim a fully green all-repository run;
- the VPG commit-ceiling performance audit remains above its aspirational
  threshold on this machine (approximately 89 ms p99 versus a 50 ms target).
  Durable space growth is fixed; full-projection commit latency is not.

One SIGKILL journal audit failed once during the long combined run but passed
when its complete test file was rerun independently. It is tracked as a
Windows/full-suite isolation flake rather than presented as a resolved
production reliability guarantee.

## Known limitations

- Single-host/local only; no distributed cluster scheduler, leader election,
  multi-writer CAS, or shared physical device inventory.
- CPU/RAM/GPU/VRAM/model-slot accounting is logical per-Agent capacity
  admission, with no dynamic telemetry, physical isolation, quota/RPM/TPM,
  preemption, fairness, or starvation guarantee.
- Durable Scheduler replay assumes one writer and recovers logical state, not
  arbitrary Python memory, call stacks, or in-flight code.
- The Lease-fenced Evidence path closes the main SDK release/reassignment race,
  but Facts, Action, Claim completion, Lease release, driver effects, and
  external systems are not one cross-plane atomic transaction. External
  irreversible effects are not exactly-once.
- Arbitrary executor/verifier callbacks are not automatically sandboxed.
- VPG deletion tombstones and incremental derive/validate/hash are future work.
- Context VM is implemented independently but is not wired into the primary
  `AgentOS` composition root.
- No production hosted service, web dashboard, general belief-revision/
  contradiction solver, or statistically powered real-model/real-GPU/
  competitor benchmark is included.
